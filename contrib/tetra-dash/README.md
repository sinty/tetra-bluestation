# tetra-dash — панель наблюдения и управления базовой станцией

**In brief (English):** a small web dashboard for `bluestation-bs`. It implements the
server side of the station's `[telemetry]` and `[command]` WebSocket interfaces,
shows registered radios, group calls and backhaul state, sends SDS through the
control channel, and starts/stops the station unit. Python + `websockets`, no other
dependencies. Everything below is in Russian, matching the operator's engineering log.

---

Панель поднимает серверную сторону двух интерфейсов, которые станция открывает
наружу, и добавляет к ним веб-страницу:

```
:9001  телеметрия   сабпротокол bluestation-telemetry-v1   станция -> панель
:9002  управление   сабпротокол bluestation-control-v1     панель <-> станция
:8088  браузер      HTML + WebSocket /ws
```

Слушает панель, подключается станция — в её конфигурации секции `[telemetry]`
и `[command]` задают адрес и порт.

## Что показывает и что умеет

- зарегистрированные рации и их группы;
- групповые вызовы в обе стороны;
- состояние магистрали и самой станции;
- отправку SDS выбранной рации;
- пуск и останов станции, причём состояние переживает перезагрузку машины.

## Разобранное по дороге

Документации на эти интерфейсы нет, всё установлено чтением исходников —
может пригодиться тому, кто будет писать свой клиент:

**Кадры двоичные, внутри JSON.** Оба интерфейса шлют `Message::Binary`, а тело —
внешне тегированный enum serde: `{"MsRegistration":{"issi":1234567}}`. В коде есть
и bitcode-кодек, но воркеры выбирают именно JSON.

**Сабпротокол обязателен.** Станция шлёт `Sec-WebSocket-Protocol`, и сервер должен
его подтвердить, иначе рукопожатие не состоится.

**Секция конфигурации называется `[command]`, а не `[control]`.** Поле структуры —
`control`, ключ TOML — `command`. Расхождение в самом апстриме; `[control]`
не парсится и станция падает с `Unrecognized top-level fields`.

**Телеметрия отдаёт всего четыре события** — регистрация, дерегистрация, привязка
и отвязка групп. Ни состояния магистрали, ни вызовов там нет, поэтому панель
дочитывает их из журнала systemd. В интерфейсе источник каждой строки подписан,
чтобы структурные данные не смешивались с разбором текста.

**`SendSds` требует зарегистрированного получателя.** Проверка `is_registered(dest_ssi)`
выполняется и для групповых адресов, поэтому групповая рассылка через этот канал
не проходит. Текст кодируется как SDS-TL: `0x82`, затем схема — `0x01` для латиницы,
`0x1A` для UCS-2.

**Ответ на `SendSds` приходит по тому же каналу** как `SendSdsResponse { handle, success }`,
сопоставление — по `handle`.

## Установка

Подробности и порядок шагов — в [deploy/](deploy/), там же примеры юнитов systemd,
правило polkit и образец конфигурации. Коротко:

```sh
sudo install -m 0640 deploy/tetra-lab.conf.example /etc/tetra-lab.conf   # и заполнить
python3 -m venv ~/tetra-dash-venv && ~/tetra-dash-venv/bin/pip install websockets
```

Единственная зависимость — `websockets` (проверено на 17.1).

## Безопасность

Панель умеет включать и выключать передатчик, поэтому:

- по умолчанию слушает `127.0.0.1`; при `DASH_BIND="0.0.0.0"` пароль обязателен,
  иначе управление передатчиком открыто всей локальной сети;
- права на юнит выдаются правилом polkit ровно на пуск и останов одного юнита —
  не через `sudo`, чтобы с юнита панели не пришлось снимать `NoNewPrivileges`;
- состояние «нужна ли станция после перезагрузки» хранится флаговым файлом,
  который проверяется через `ConditionPathExists`. Так панели не нужны права
  `enable`/`disable`: они в polkit не проверяются по конкретному юниту и означали бы
  власть над всеми юнитами сразу.
